# Moteur de recherche documentaire intelligent

A French document search engine (TALN project): it finds relevant documents even when
the query and the document use different words. It runs hybrid retrieval: BM25 on
lemmatized text plus BGE-M3 embeddings, fused with a tuned weight, with an optional
reranker. Everything runs locally and offline in one Streamlit page.

- Full plan: `Plan_Moteur_Recherche_Documentaire.pdf`
- Changes to the plan: [docs/plan_addendum.md](docs/plan_addendum.md). It covers the optional
  course components (WordNet, word2vec) and the multi-domain scope: the Alloprof dataset and
  the two-part evaluation.

## Setup

Python 3.12 recommended.

```powershell
python -m venv .venv
.venv\Scripts\activate
# GPU (NVIDIA) only: install the CUDA build of torch first
pip install torch --index-url https://download.pytorch.org/whl/cu128
pip install -r requirements.txt          # or requirements-lock.txt for the exact tested versions
python scripts/download_models.py        # add --light on a weak laptop, --reranker for the cross-encoder
```

Models are stored in `models/hub/` inside the project (see `search/config.py`), not in
your user profile.

### Reuse models already on your machine

If BGE-M3 or the reranker is already downloaded for another project, link it in
instead of downloading 6 GB again. No copy is made and no admin rights are needed:

```powershell
New-Item -ItemType Junction -Path models\hub\models--BAAI--bge-m3 -Target "<other project>\models\hub\models--BAAI--bge-m3"
```

## Phase 0 benchmark

```powershell
python scripts/bench_embeddings.py               # auto device
python scripts/bench_embeddings.py --device cpu  # worst case
```

Results on the dev machine (i7-10750H, RTX 2060 6 GB), 100 chunks of ~220 words,
extrapolated to 1,500 chunks:

| Model | Device | Index 1,500 chunks | Query | Memory |
|---|---|---:|---:|---|
| BGE-M3 (1024 d) | GPU | ~1.5 min | 48 ms | 2.6 GB VRAM |
| BGE-M3 (1024 d) | CPU | ~26 min | 134 ms | 2.7 GB RAM |
| multilingual-e5-small (384 d) | GPU | ~0.2 min | 15 ms | 0.6 GB VRAM |
| multilingual-e5-small (384 d) | CPU | ~2.6 min | 24 ms | 1.7 GB RAM |

**Decision:** BGE-M3 stays the main model. Build the final index on the GPU machine and
share the `index/` folder. A CPU laptop only embeds the query (~0.1 s). Teammates can
develop with e5-small (`EMBED_MODEL` in `search/config.py`) and switch back for the
final run.

## Get the data

The main corpus and benchmark is **Alloprof** (`lyon-nlp/alloprof`, Apache 2.0): French
course pages from alloprof.qc.ca and real student questions with their relevant pages.

```powershell
python scripts/fetch_alloprof.py      # ~23 MB download, all subjects except "english"
```

It writes:
- 2,350 pages to `data/corpus/alloprof/<subject>/`, with titles and subjects in each
  folder's `.metadata.json`
- 2,281 test and 300 dev questions to `eval/alloprof/queries.json` and `qrels.csv`

Downloaded data stays local (git-ignored). Your own documents go in another sub-folder,
for example `data/corpus/divers/`. Each first-level sub-folder is a **collection**.

## Build the index

Supported formats: **PDF, TXT, DOCX, CSV, HTML**. Files in any other format are listed
as skipped. Put the documents in `data/corpus/` (sub-folders allowed), then:

```powershell
python scripts/build_index.py                                  # data/corpus -> index/
python scripts/build_index.py --corpus tests/fixtures/corpus   # synthetic test corpus
```

Phase 1 writes:
- `index/chunks.parquet`: one row per chunk, with `chunk_id`, `doc_id`, `collection`,
  `format`, `title`, `page`, `n_words`, `text_raw` (for snippets), `text_index` (what is
  indexed: title + text when `CHUNK_TITLE_PREFIX` is on) and `meta` (JSON)
- `index/skipped.json`: scanned or unreadable files
- `index/meta.json`: counts and settings

On Alloprof: 2,350 documents → 7,074 chunks in about 5 seconds.

Phase 2 adds the lexical branch:
- `text_lex` column in `chunks.parquet`: the chunk after `lexical_prep` (spaCy lemmas,
  no stopwords, lowercase, no accents)
- `index/tfidf.pkl`: TF-IDF vectorizer and matrix
- `index/bm25/`: BM25 index (bm25s)

With it the Alloprof build takes about 2 minutes, almost all of it spaCy.

Optional per-folder metadata: a `.metadata.json` in any corpus folder can set a file's
title and extra fields, e.g. `{"page.txt": {"title": "Les fractions", "subject": "math"}}`.

## Test corpus and tests

`tests/fixtures/corpus/` holds 23 files: 10 CVs (`cv/`), 6 job offers (`offres/`) and 7
other documents (`divers/`): an 11-page activity report, an administrative procedure
with a table, a news article, a scientific abstract, a decree excerpt and two CSV tables.
They are **synthetic and fictional**, generated by `scripts/make_fixtures.py`, which
keeps existing files unless `--force`. They cover the hard cases:
- a scanned PDF
- repeated headers and footers
- line-end hyphens
- HTML navigation and scripts
- a section continuing across pages
- DOCX tables
- legal abbreviations (`Art. 1er`, `art. L. 541-1`)
- junk PDF metadata titles
- Windows-1252 text and CSV files (`;` delimiter, quoted cells with line breaks, empty cells)

```powershell
python -m pytest
```

## Run

```powershell
streamlit run app.py
```

The page searches in TF-IDF or BM25 mode, with filters by collection and file type. It can
open any index folder of the project (`index/`, or `index_test/` built with `--index`).
The other modes arrive in Phases 3 and 4.

## Layout

```
app.py              Streamlit page
search/             extract, clean, chunk, lexical, semantic, spelling, fusion, rerank, engine
                    + optional wordnet_expand, word2vec (course Chapter 3)
data/corpus/        documents (not committed: may hold personal data)
index/              generated index files
eval/               queries.json, qrels.csv, metrics.py, run_eval.py
scripts/            download_models, check_env, bench_embeddings, fetch_alloprof,
                    make_fixtures, build_index
tests/              pytest suite + synthetic fixture corpus
docs/               plan addendum, phase reviews
```
